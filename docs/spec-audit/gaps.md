# Gaps

Worklist for the spec-audit loop. Each entry is one spec claim that has not
been verified against this repo. Ranked by risk to the timeline, highest first.

Status: `open` | `blocked-on-human` | `resolved`

Scope note: only claims SPEC.md makes about **pedro-agentware** are listed.
Claims about kei, kei-proxy, kei-web, registry, database, and pedro-tag are out
of scope for this audit. Nothing below has been checked against source — this
pass is worklist construction only.

## Open

### Tier 1 — blocks the day-3 schema freeze or the day-5 de-risk gate

- [ ] G-036 status:open risk:high — **NEW.** ADK's tool callbacks may not fire during live/streaming execution. [Issue #4704](https://github.com/google/adk-python/issues/4704) reports `_execute_single_function_call_live()` invoking agent callbacks but skipping plugin-manager callbacks. If the §8 demo path streams, policy enforcement has a hole and "intercepts every tool call" fails on the ADK backend specifically. Test explicitly on day 5, per `parity.md` §5.4. **Security-relevant: a bypass, not a bug.**

- [ ] G-037 status:open risk:medium — **NEW.** Field-population divergence between backends if SC-007 slips. ADK's `after_tool_callback`/`after_model_callback` give the ADK backend a post-execution seam the native Pydantic path lacks (SC-006), so ADK could populate `resources_touched[]`, `latency_ms`, and tokens while the native path could not — failing §2.3's Audit invariant ("same fields populated with the same semantics across adapters") in the very demo that is supposed to prove it. See `parity.md` §5.6.

- [ ] G-033 status:open risk:high — **NEW.** Post-execution fields require restructuring the emission point, not adding fields. The audit record is built and `Record()`d before the executor runs (`go/middleware/middleware.go:41-48` vs. line 64), and `Auditor` (`go/middleware/audit.go:13-16`) has no amend method. Every §4 field knowable only after the call — `resources_touched[]`, `latency_ms`, `error`, `retry_count`, and all three token fields — is unreachable without a two-phase emit or a mutable record handle. Estimate this before committing to the day-3 freeze; see SC-007. **This is a design change — flagged for human decision per rule 1.**

- [ ] G-034 status:open risk:high — **NEW.** Filtered calls write unredacted args to the audit store. The record captures `args` at `go/middleware/middleware.go:44`; `ActionFilter` redacts at lines 58-62, after. A PII-redaction policy therefore protects the tool and exposes the audit log — inverted from §4's stated intent. In Go the map is aliased and mutated in place, so what a sink observes depends on whether it serializes on receipt or holds the reference. See SC-009.

- [ ] G-035 status:open risk:high — **NEW (security).** Two independent silent fail-open paths. (a) `getCallerContext` returns `CallerContext{Trusted: true}` when no caller is attached (`go/middleware/middleware.go:77-84`) — a forgotten `WithCallerContext` is a privilege escalation, audited with an empty `SessionID`. (b) `InferenceExecutorConfig.ToolExec` is typed as the bare `ToolExecutor` interface (`go/executor/executor.go:76`), which `tools.RegistryExecutor` satisfies directly — a config omitting the middleware executes every tool with no policy and no audit row, and compiles. See D-002, SC-010. **Rule 2 flag: policy enforcement is bypassable by construction.**

- [ ] G-042 status:open risk:medium — **NEW, scoped down by DEC-004.** Authorization is a network call in the demo path (`kei:cmd/proxy/abac.go:52-58`), accepted as a hackathon loss; local-config + mutex lookup documented in kei for later. Residual: §4 `latency_ms` will include authorization time unless timed separately at the emission point. Cheap to handle, easy to get silently wrong. See SC-019.

- [ ] G-048 status:open risk:high — **NEW.** `cached_tokens` is not captured anywhere. `grep -rn "cached\|Cached" go/llm/ go/middleware/` returns nothing; `TokenUsage` has three fields (`go/llm/response.go:19-23`) and the wire unmarshal declares three keys (`go/llm/server.go:106-109`), so the value is not read even when reported. §5 calls context caching out as materially affecting effective rates. Small fix, but absent rather than unplumbed. See SC-025.

- [ ] G-049 status:open risk:high — **NEW (schema freeze).** Token usage is per model *turn*; the audit record is per *tool call*. One turn yields many tool calls (`go/executor/inference.go:119`), so §4's per-call record cannot carry per-turn tokens without an attribution rule — split, attribute-to-first, or emit turn-level rows. §5's "spend per invocation" and the delegation rollup both depend on the choice. Applies equally to kei's `action_log`, which has no turn concept (`kei:cmd/proxy/store.go:23-32`). **Needs a decision before the freeze.** See SC-026.

- [ ] G-043 status:open risk:high — **UPDATED, narrowed by verification.** Per DEC-005 kei owns the audit log, but token data never leaves agentware's process. Capture is real (`go/llm/response.go:8,19-23`, populated at `go/llm/server.go:134-138`); delivery is not — the sole non-test consumer outside `go/llm/` is context-window accounting (`go/middleware/inference/inference.go:77-79`, Python identical at `middleware/inference.py:130-131`), which reads `TotalTokens` only and discards the prompt/completion split. `AuthorizeRequest`/`AuthorizeResponse` (`kei:cmd/proxy/abac.go:13-27`) carry no usage fields and `action_log` has no columns for them (`kei:cmd/proxy/store.go:23-32`). §5's cost story has a source but no wire. Also still unresolved: kei's row is written before tool execution (`kei:cmd/proxy/authorize.go:113`), leaving `latency_ms`, `error`, `retry_count`, `resources_touched[]` unpopulatable there. See SC-024, SC-020.

- [ ] G-044 status:open risk:medium — **NEW (rule 3).** `decision` vocabularies are incompatible, not just misspelled. kei: `permit`/`deny`/`enrollment_required` (`kei:cmd/proxy/authorize.go:63,105,110`). agentware: `allow`/`deny`/`filter` (`go/middleware/types.go:7-11`). agentware cannot represent `enrollment_required`; kei cannot represent `filter`. Supersedes SC-005 as the larger issue. See SC-022.

- [ ] G-045 status:open risk:high — **NEW, owner-prioritized for fix. Scope: Python only (DEC-006).** kei fails closed (`kei:cmd/proxy/authorize.go:53-55`); agentware fails open. **Correction to an earlier entry in this audit**: Python was described as not having the caller-context fail-open. It does, by a different route — `CallerContext.trusted` defaults to `True` (`python/src/pedro_agentware/middleware/types.py:51`) and `ExecuteRequest.caller_ctx` defaults to `field(default_factory=CallerContext)` (`python/src/pedro_agentware/executor/executor.py:31`), so an `ExecuteRequest` with no caller runs the whole loop anonymous-and-trusted with no type error. Fix: `trusted: bool = False`, and drop the `default_factory` so the field is required. See D-008.

- [ ] G-050 status:open risk:high — **NEW (security, rule 2).** Go's hermes adapter reimplements the middleware instead of delegating to it, and the copy drops `ActionFilter`. `HermesMiddlewareAdapter.Execute` (`go/adapters/hermes/adapter.go:216-245`) inlines caller-lookup → evaluate → record → deny-check → execute, but has no filter branch anywhere in the file: a policy returning `ActionFilter` falls past the deny-check to `a.executor.Execute` at line 246 with **unredacted args**, silently becoming an allow. Same policy, same subject, different outcome depending on path — §2.3's Policy invariant failing where two enforcement paths already coexist. See D-010.

- [ ] G-051 status:open risk:high — **NEW.** `parity.md` §2's proposed `AgentBackend` interface **already exists and is the wrong shape** (`python/adapters/base.py:7-17`) — no caller parameter, and it returns `AgentResult` (`base.py:32-43`) where middleware's `ToolExecutor` returns `tuple[Any, bool, str]` (`middleware/middleware.py:15`). The two protocols are structurally incompatible, so no Python adapter can be passed to `MiddlewareImpl`. `grep -rn "AgentBackend\|AgentResult" python/src/` returns nothing — the middleware has never referenced the adapter contract. The design note must reconcile with the existing protocol rather than introduce a same-named new one. See D-011.

- [ ] G-046 status:open risk:high — **UPDATED, widened by verification.** Not a Pydantic-adapter defect — a defect in the Python adapter **contract**. `AgentBackend.execute(tool_name, args)` (`python/adapters/base.py:10`) takes no caller, and every implementer matches: hermes (`adapters/hermes/adapter.py:35`), kitaru (`adapters/kitaru/adapter.py:43`), pydantic (`adapters/pydantic/adapter.py:39`), pydantic-async (`adapters/pydantic/adapter.py:156`). No Python adapter can evaluate policy because the protocol supplies no identity to evaluate against. Cross-language divergence: Go's hermes adapter *does* enforce (G-050), Python's does not — so whether policy runs at all depends on the implementation language. See D-011.

- [ ] G-047 status:open risk:medium — **NEW.** TypeScript `CallerContext` not yet checked for the D-008 dataclass-default pattern. Out of scope per DEC-006 but should be confirmed before the deferred all-three fix is scoped. Cheap check.
